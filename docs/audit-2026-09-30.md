# 全量审计报告 · 2026-09-30

起因：`shuffleOptions` 的答案重映射方向错误（约一半客观题答案错位）暴露出
「导入期映射失败被静默兜底掩盖」这类缺陷模式。本次审计按同一模式全仓扫描：
数据完整性 × 代码逻辑 × 跨文件契约 × 平台路径。共 **19 项问题**（高危 7、
中危 5、低危 7），全部修复；314 项测试全绿，冻结契约模块覆盖率 87.94%。

修复涉及三个层次：**已发布数据**（题库 JSON 就地幂等修复 + 题库版本 v7）、
**根因**（导入/解析脚本 + 运行时代码）、**回归测试**（为每个高危修复补行为级断言）。

## 高危（直接污染分数效度或泄题）

### A1. 判断题难度整体错位一档【数据 + 根因】
- **位置**：`scripts/import-objective-bank.mjs` `partIndex()`；数据见两份客观题库。
- **缺陷**：收集第十单元判断题标签的过滤器把第八单元占位串「第701-720题」
  也算进来（不含"部分/组"），`indexOf` 整体 +1，难度阶梯被旋转一格：
  65/80 题难度标签错误（station 15 题因越界钳制碰巧正确）。最严重的是
  workshop 15 道 high 被标成 low——1PL 的 b 参数直接反号。
- **修复**：`scripts/repair-judge-difficulty.mjs` 按 levelId→声明难度回写两库
  （130 处/两库）；根因处排除占位串并在数量 ≠5 时抛错。

### A2. 实操证据维度全部塌缩为 D2/D5【数据 + 根因】
- **位置**：`scripts/import-practical-bank.mjs` `dimKeysFor()` 兜底。
- **缺陷**：源文档「考察维度」名与映射表全部不匹配时静默回落 `["D2","D5"]`——
  90 个任务（80 全量 + 10 精选）无一幸免。实操通道证据只进 D2/D5，
  六维后验的 D1/D3/D4/D6 从实操拿不到任何证据。
- **修复**：`scripts/repair-practical-dimkeys.mjs` 按「D2 为共同底座 + 逐任务
  显式第二维度（含逐条理由）」重写：D4×42、D3×23、D5×21、D1×2、D6×2；
  `dims` 中文名同步回填（原为空数组）。根因处补官方全名别名（AI结果评估与
  优化/AI伦理与合规等）+ 兜底逐题打印警告。

### A3. 3 道实操任务的交付要求里泄漏标准答案【数据 + 根因】
- **位置**：`scripts/parse-practical-docx.mjs` `extractFields()`；full-006/015/024。
- **缺陷**：instructions 归属段没有代码块边界守卫，参考答案的完整 Python 代码
  与「简要解释」混进了 requirements——该字段原样下发给学生，等于题面泄题。
- **修复**：`scripts/repair-practical-brief.mjs` 剥离代码块起始行之后的全部
  泄漏行（29-34 行/题）；解析器在 instructions 模式遇 `"""`/```` ``` ```` 即切换
  到 answer 归属。附带修复同库 80 个任务 `minutes` 为空串的问题（按精选库
  口径 low=5/medium=8/high=12 回填，根因处加兜底）。

### A4. 对话采访提问槽位滞后一档（差一 / stale closure）【运行时】
- **位置**：`src/AssessmentFlow.jsx` `send()` → `requestInterviewer()`。
- **缺陷**：`setSlotIndex(N+1)` 是异步的，`requestInterviewer` 闭包里读到的
  仍是 N——**生成的问题落在第 N 槽考点，学生的回答却按第 N+1 槽的量规打分**
  （experience 追问被按 goal 判分；第 5 槽 consolidate 的问题从未发出）。
- **修复**：`requestInterviewer` 增加显式 `slotOverride/slotIndexOverride` 参数，
  `send()` 前进时显式传入 `nextIndex` 的槽位。

### A5. 判分纪律提示词写死已废弃的五档量表【跨文件契约】
- **位置**：`src/interview-scoring.js` `judgeDiscipline()`；`.agents/skills/
  aiquos-interview-scoring/SKILL.md`；`src/interviewer.js` 注释。
- **缺陷**：同一评审提示词里锚点列七档（0/0.2/0.45/0.65/0.8/0.92/1）、纪律
  却只许五档（0/0.25/0.5/0.75/1）。LLM 按五档心智给 0.75 被 `snapToScale`
  静默改档到 0.8（跨两个校准锚，虚高约 10 分）；0.5 被压到 0.45。
- **修复**：纪律条款改写为七档表述（越界值吸附说明）；SKILL.md 的量表叙事、
  每槽锚点（程序化从 SLOT_RUBRICS 再生成为七档）、反作弊条款档位值全部同步。

### A6. 三通道融合的实操通道量纲错位【运行时】
- **位置**：`src/comprehensive-weighting.js` `fuseChannels()`。
- **缺陷**：实操通道把 σ(θ) 展示分（score）当得分率 credit 喂进 credit 锚点
  反演曲线——正确口径的 `rawScore` 字段被无视。中等 credit 0.555 被记为
  θ≈−0.23（应为 0），满分也只有 0.73（应为 1.6），实操权重 0.15 下的维度分
  系统性偏低 1–15+ 分。
- **修复**：优先 `rawScore`（credit 口径）走锚点曲线；旧快照无 rawScore 时
  退回 logit 反演展示分（其自身 sigmoid 的逆）。`WEIGHTING_VERSION` 1.1.0→1.2.0。

### A7. CAT 定档先验被隐式 N(0,1) 双重收缩【运行时】
- **位置**：`src/comprehensive-adaptive.js` `estimateRunAbility()`。
- **缺陷**：先验项 −κ(θ−θ₀) 与基线 −θ 叠加，有效先验变成 N(κθ₀/(1+κ), …)：
  κ=1、θ₀=1.6 时零证据估计只有 0.8、第一题打在 0.52——与两处文档承诺的
  「第一题直接打在 θ₀ 附近」直接矛盾；「种子即能力估计」分支实为不可达代码。
- **修复**：先验存在时**替换**基线项（先验就是能力估计，不叠加中性先验）；
  零证据估计恰为 θ₀；SE 公式（κ+ΣI）与估计器口径随之对齐。κ 网格实验的
  提前停测结论不受影响（SE 口径未变）。

## 中危

### B1. 后端权威 CAT 接受客户端伪造证据【worker】
- **位置**：`worker/comprehensive-quiz.js` `normalizeSession()` / `applyOutcomeToSession()`。
- **缺陷**：`session.evidence` 透传只查 `typeof credit === "number"`——credit 99/−5
  不钳制、伪难度（`difficulty:"bogus"` → ANCHOR undefined → 导数 NaN → θ 钉在
  −8）、NaN 证据全部被采信；`dimensionCounts` 无校验合并可伪装维度已覆盖、
  关闭 coverage 兜底。与文件头"never trusted from the wire"的声明直接矛盾。
- **修复**：`sanitizeEvidence`（credit 钳 [0,1]、难度白名单、dimKeys 过滤到
  D1–D6，非法整条丢弃）+ `sanitizeDimensionCounts`（有限正整数、键白名单）
  + usedQuestionIds/evidence 上限 + outcome.credit 同口径。附恶意载荷回归测试。

### B2. 离线时对话启发式分从未进入证据（注释承诺虚假）【运行时】
- **位置**：`src/AssessmentFlow.jsx` `gradeAnswerInBackground()`。
- **缺陷**：注释称「启发式临时分已垫底…权威分原位覆盖」，实现里临时分只进
  UI 芯片；打分轨失败静默吞掉 → 断网/无 Key 时六维的对话证据全部缺失。
- **修复**：打分轨失败或不可解析时，启发式保守分经 `recordCredit` 垫底入证据
  （取高规则保证后续权威分只升不降）；正常路径不变（避免报告看到中间值抖动）。

### B3. 「达到评分标准：」元信息行污染评分与启发式【运行时】
- **位置**：`src/practical-scoring.js`；`src/AssessmentFlow.jsx` 客户端兜底。
- **缺陷**：精选版（默认 B 版）10 个任务的 requirements 全部是导入器从量规
  维度名推导的「达到评分标准：X」行（前缀"达到"绕过 `^评分标准` 过滤）——
  进入覆盖率分母把离线启发分压到底档，发给评委也与量规重复。
- **修复**：新增 `scoringRequirements()`（两种前缀都排除）供评委消息与
  启发式使用；展示层 `deliveryRequirements` 保持原样（简报里仍是验收提示）。

### B4. Windows 路径拼接 bug（已知模式的最后一处）【测试】
- **位置**：`tests/scoring-integration.test.mjs`。
- **缺陷**：`href.replace("file://","")` 在 Windows 产生 `/C:/...` → `C:\C:\...`，
  vendor CLI 金样对比测试在 Windows 必红。全仓唯一残留实例。
- **修复**：`fileURLToPath()`。

### B5. sites-worker 测试在 CI 顺序下必红【测试】
- **位置**：`tests/sites-worker.test.mjs`；`.github/workflows/ci.yml`。
- **缺陷**：两条测试断言 `dist/` 构建产物，而 CI 的单测步骤在 build 之前、
  Sites 打包还需不入库的 `.openai/hosting.json`——全新环境必然假红。
- **修复**：产物缺失时显式 skip（附原因说明），本地完整构建后真跑。
