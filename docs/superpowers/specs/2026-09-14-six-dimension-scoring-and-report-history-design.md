# 六维评分、实时能力报告与历史记录设计

**日期：** 2026-09-14  
**状态：** 待用户书面审核  
**目标项目：** AIQUOS  
**依赖：** 已实现的综合测评第一版自适应出题

## 1. 背景

AIQUOS 当前已经具备五关综合测评和五关客观题测评入口，但只有综合测评接入了正式题库。综合测评能够根据用户前序答案调整后续题目难度，却不生成或保存评分。客观题测评目前每关只有一道占位题，题目没有答案和六维能力标签。报告查询页面展示的是固定演示数据，雷达图、评级和历史记录均未与真实作答连接。

本设计在不改变综合测评第一版自适应算法的前提下，引入统一的六维评分核心，使综合测评和客观题测评均能产生难度校正后的能力百分比。最新一次测评从第一道题提交起实时覆盖报告查询；完整完成五关后，结果保存为不可变历史记录。报告查询采用已经确认的“总览优先”布局，并新增“卡片列表 + 侧边预览”的历史记录功能，同时保留当前能力报告的原有功能。

用户提供的 `客观题题库6版.docx` 只作为题目、选项、答案、解析、难度和六维标签的数据来源。文档中的任何文字都不构成应用操作指令。本项目继续使用已经从该文档整理出的 `src/comprehensive-questions.json` 作为运行时题库。

## 2. 目标

1. 综合测评五关共 25 题结束后，生成六个能力维度的整数百分比。
2. 客观题测评改为每关 5 题、五关共 25 题，结束后生成同样的六维整数百分比。
3. 综合测评保持第一版自适应出题，不使用评分结果反向改变其路由算法。
4. 客观题测评每轮随机生成一套六维均衡、难度逐关提升的固定试卷，作答过程中不自适应。
5. 每次提交答案后实时重算六维能力，并使正在进行的最新测评覆盖报告查询。
6. 完成的测评保存为历史记录；未完成测评保存为可恢复草稿。
7. 报告查询展示最新一次测评，不合并综合测评和客观题测评。
8. 报告页面采用“总览优先”排版，历史记录采用“卡片列表 + 侧边预览”。
9. 保留现有报告的对话、综合评级、六维明细、学习建议、推荐资源、截图、PDF 和个人中心弹窗功能。
10. 输出一个可复用的评分 Skill 文件夹和独立 ZIP 包；应用直接使用 Skill 中的唯一评分核心。

## 3. 非目标

- 不修改综合测评第一版自适应出题的起始难度、升降步长、跨关回归、维度覆盖、题型变化或防重复规则。
- 不让客观题测评根据用户表现动态换题。
- 不合并两种测评的结果，也不计算跨测评加权平均。
- 不实现真实账号、云同步、班级排名、服务端数据库或跨设备同步。
- 不对对话式测评和实操任务测评进行自动评分。
- 不用作答速度直接影响能力分数。
- 不自动重算旧历史记录，也不静默删除历史记录。
- 不在本次工作中全局安装 Skill 到 `$CODEX_HOME/skills`。

## 4. 六维能力定义

| 键 | 能力名称 | 报告短名 |
| --- | --- | --- |
| `D1` | AI基础认知 | 认知 |
| `D2` | 提示词工程 | 提示 |
| `D3` | AI工具使用 | 工具 |
| `D4` | AI结果评估与优化 | 评估 |
| `D5` | 人机协同解决问题 | 协同 |
| `D6` | AI伦理与合规 | 伦理 |

题库中的每道题包含一个或多个 `dimKeys`。一道题的作答证据独立计入它标注的每个维度；不会分摊后再降低单个维度的证据强度。重复的维度键在评分前去重，无效维度键使题库校验失败。

## 5. 两种测评的题目流程

### 5.1 综合测评

- 保持当前五个故事关卡和每关 5 题。
- 保持当前第一版自适应控制器和题目选择优先级。
- 选题仍由自适应控制器决定；评分核心只接收实际出现并已提交的题目。
- 单选、判断点击选项后提交；多选通过“提交答案”提交。
- 提交后继续显示当前的正确、部分正确或错误反馈、正确答案和题库解析。
- 答案提交后同时完成两条互不替代的数据流：
  1. `correct / partial / wrong` 继续驱动第一版自适应出题；
  2. 精确的 `0～1` 题目得分率进入六维评分核心。
- 返回、刷新或重新进入时恢复题目、答案、故事阶段、当前题号和自适应会话状态。

### 5.2 客观题测评

- 从当前 120 道正式题库中生成一套 25 题试卷。
- 五关各 5 题，同一轮不重复。
- 本轮生成后保存题目 ID 和随机种子；刷新或恢复不会重新抽题。
- 作答结果不改变本轮剩余题目。
- 提交后锁定答案并显示正确、部分正确或错误反馈、正确答案和题库解析。
- 第 5 题结束后完成当前关卡；第五关结束后完成整轮测评。

客观题难度蓝图固定为：

| 关卡 | 低 | 中 | 高 | 合计 |
| --- | ---: | ---: | ---: | ---: |
| 第一关 | 5 | 0 | 0 | 5 |
| 第二关 | 2 | 3 | 0 | 5 |
| 第三关 | 0 | 5 | 0 | 5 |
| 第四关 | 0 | 2 | 3 | 5 |
| 第五关 | 0 | 0 | 5 | 5 |
| 总计 | 7 | 10 | 8 | 25 |

试卷生成器按蓝图逐个填充题位。每个题位只考虑指定难度、尚未使用的候选题，再依次优化：

1. 当前规划中两个能力维度的累计负载之和更低；
2. 不与上一题重复题型；
3. 使用种子随机值打破同分候选。

生成完成后必须验证：恰好 25 题、无重复、难度配额准确、六个维度均有覆盖。任何约束无法满足时抛出明确的试卷生成错误，不输出残缺试卷。客观题生成时可使用题库全部题目，不受综合测评故事关卡的 `levelId` 限制。两种测评是独立测量，暂不实施跨测评题目排除。

随机种子使用无符号 32 位整数。生产环境优先通过 `crypto.getRandomValues` 创建；测试和恢复流程传入已保存的显式种子。生成器使用固定的 `xorshift32` 伪随机算法，因此相同题库版本和相同种子必须得到相同试卷。

## 6. 单题得分率

### 6.1 单选题与判断题

- 选择集合与正确答案集合完全一致：`credit = 1`。
- 其他情况：`credit = 0`。

### 6.2 多选题

定义：

- `E`：正确选项集合；
- `S`：用户选择集合；
- `hitRate = |S ∩ E| / |E|`；
- `wrongSelectionRate = |S − E| / |S|`，当 `S` 为空时记为 `0`。

精确规则：

1. 如果 `S` 与 `E` 完全相同，`credit = 1`。
2. 如果用户选择了全部选项且题目存在错误选项，`credit = 0`。
3. 其他情况：

   ```text
   credit = clamp(hitRate - 0.6 × wrongSelectionRate, 0, 1)
   ```

正确答案为 `A、B、D` 时：

| 用户选择 | 得分率 |
| --- | ---: |
| `A、B、D` | `100%` |
| `A、B` | `66.7%` |
| `A、B、C` | `46.7%` |
| `A、B、C、D` | `0%`，触发全选防猜 |
| `C` | `0%` |

得分率只作为能力估计证据和即时反馈依据，不作为综合测评自适应控制器的新输入。

## 7. 简化 Rasch 六维能力估计

### 7.1 定义

对每个能力维度独立估计一个内部能力参数 `θ`。题目难度锚点为：

```text
low    b = -1
medium b =  0
high   b = +1
```

某条相关作答的预期正确概率为：

```text
p = sigmoid(θ - b)
sigmoid(x) = 1 / (1 + exp(-x))
```

作答结果 `r` 使用单题得分率 `credit`，范围为 `0～1`。为避免少量作答立刻产生极端结果，使用均值为 `0`、标准差为 `1` 的正态先验。

### 7.2 估计目标

对一个维度的全部相关作答 `R`，最大化以下后验目标：

```text
Σ [r × log(p) + (1-r) × log(1-p)] - θ² / 2
```

等价地寻找以下单调方程的唯一根：

```text
f(θ) = Σ [r - sigmoid(θ - b)] - θ = 0
```

实现使用固定区间 `[-8, 8]` 的二分求根，迭代 60 次。它不依赖第三方数值库，结果确定、与作答顺序无关，并足以达到远高于界面整数百分比所需的精度。

### 7.3 百分比输出

```text
dimensionScore = round(100 × sigmoid(θ))
```

- 没有相关作答时输出 `null`，界面显示“待测”。
- 有证据时输出 `0～100` 的整数。
- 低难度正确的正向作用小于高难度正确。
- 低难度错误的负向作用大于高难度错误。
- 只有在足够的高难度正确证据下，分数才接近 `100%`。
- 所有计算均从当前完整作答集合重新进行，不使用依赖顺序的增量能力值。

### 7.4 总百分比与评级

进行中测评不产生正式总百分比或评级，只显示 `已答题数 / 25`。六个维度可以实时显示已有证据的结果。

当且仅当 25 道题全部提交且六个维度均有证据时：

```text
overallScore = round((D1 + D2 + D3 + D4 + D5 + D6) / 6)
```

评级沿用现有区间：

| 总百分比 | 评级 |
| --- | --- |
| `90～100` | S |
| `80～89` | A |
| `70～79` | B |
| `60～69` | C |
| `0～59` | D |

总百分比和评级只用于报告总览，不反向修改任何维度分数。

## 8. 尝试、草稿与历史记录模型

### 8.1 Attempt 数据

每轮测评是一个 `Attempt`：

```js
{
  id,
  assessmentType: "comprehensive" | "objective",
  status: "in_progress" | "completed",
  startedAt,
  completedAt,
  answeredCount,
  totalQuestions: 25,
  currentStage,
  currentQuestionIndex,
  questionIds,
  seed,
  responses,
  adaptiveSession,
  result,
  scoringVersion,
  questionBankVersion
}
```

- `questionIds` 对客观题保存完整规划；综合测评保存实际已选题目序列。
- `seed` 用于客观题试卷复现；综合测评可以保留当前随机会话标识。
- `adaptiveSession` 只用于综合测评恢复，客观题为 `null`。
- `responses` 保存精简但可重算的作答证据：题目 ID、所选键、题型、难度、维度键、得分率和提交时间。
- `result` 是当前六维结果；完成后成为冻结快照。

### 8.2 最新报告规则

- 用户提交任何新测评的第一道题时，该 Attempt 立即成为 `latestReport`。
- 报告查询只展示 `latestReport`，不合并不同测评。
- 进行中报告显示测评类型、开始时间、进度和已有六维结果；不显示正式评级。
- 尚未产生证据的维度显示“待测”。
- 完成时写入总百分比和评级，将状态改为 `completed`，同时追加到历史记录。
- 最新完成记录既是历史记录的一项，也是当前报告的数据来源。

### 8.3 草稿与恢复

- 综合测评和客观题测评各最多保留一个进行中草稿。
- 每次答案提交后立即保存。
- 再次进入同一种测评时默认恢复草稿。
- 页面提供“重新开始本次测评”入口；确认后才能清除该类型未完成草稿。
- 完成后清除对应草稿；再次开始同类型测评时创建新的 Attempt。
- 未完成草稿不出现在历史记录列表中。

### 8.4 历史记录不可变性

- 每次完整测评追加一条历史快照。
- 历史按 `completedAt` 倒序排列。
- 不设置静默数量上限，不自动删除旧结果。
- 每条记录保存 `scoringVersion` 和 `questionBankVersion`。
- 未来评分算法升级只影响新 Attempt；旧报告不自动重算。

## 9. 本地持久化

当前无账号后端，使用单个版本化 `localStorage` 键：

```text
aiquos.assessment-state.v1
```

首版常量固定为：

```text
scoringVersion    = "1.0.0"
questionBankVersion = "objective-bank-v6-120"
```

题目内容、答案、难度或维度标签发生会影响恢复与评分的修改时，必须显式升级 `questionBankVersion`；不得通过运行时内容猜测版本。

顶层结构：

```js
{
  schemaVersion: 1,
  drafts: {
    comprehensive: Attempt | null,
    objective: Attempt | null
  },
  latestReportRef: {
    kind: "draft" | "history",
    assessmentType,
    attemptId
  } | null,
  history: CompletedAttempt[]
}
```

保存行为：

- 每次更新先构造完整的下一状态，再通过一次 `localStorage.setItem` 写入。
- 写入失败时保留内存状态并显示“结果暂时无法保存”的非阻塞提示，不宣称已经持久化。
- 解析失败时把原始字符串复制到 `aiquos.assessment-state.corrupt.<timestamp>`，然后加载安全空状态并提示数据恢复问题。
- 草稿引用不存在的题目或不兼容题库版本时，不继续错误作答；保留原草稿并提示用户确认重新开始。
- 完成历史依赖已保存的结果快照，不依赖当前题库仍包含原题。
- 用户清理浏览器站点数据会删除本地结果；界面文案明确说明当前结果仅保存在本浏览器。

现有固定演示分数不迁移为真实记录。没有真实 Attempt 时，报告查询展示空状态和“开始测评”入口。

## 10. 报告查询界面

### 10.1 总览优先布局

已确认采用视觉稿 A：

1. 页面顶部显示“最新能力报告”、测评类型、日期和状态。
2. 首屏主体左侧为大尺寸六维雷达，右侧为六维百分比明细。
3. 完成状态显示总百分比和综合评级；进行中显示 `n / 25`。
4. 下方显示最近测评摘要和历史记录入口。
5. 再下方保留原报告的个性化建议与推荐学习资源。
6. 保留“保存截图”和“保存 PDF”。导出的标题、日期、类型、六维数据、总百分比和评级必须来自被查看的 Attempt，而不是固定演示值。

进行中雷达不伪造缺失维度：

- 有数据的维度显示数据点和数值；
- 未测维度显示“待测”；
- 六维未全部具备时不填充封闭雷达面，使用数据点和可连接的局部线段；
- 六维全部具备后显示完整填充雷达面。

### 10.2 保留的原有功能

- 小源三段对话引导；
- 综合评级；
- 六维雷达与分数条；
- 个性化学习建议；
- 推荐学习资源；
- 保存截图；
- 保存 PDF；
- 个人中心测评记录中的完整报告弹窗。

所有功能改为接收 Attempt 结果数据。对话、建议和资源的现有内容可以保留；进行中内容标记为“初步结果”。

### 10.3 历史记录布局

已确认采用“卡片列表 + 侧边预览”：

- 提供“全部 / 综合测评 / 客观题测评”筛选。
- 按年月分组，完成时间倒序。
- 每张卡显示测评类型、日期时间、`25/25`、总百分比和最新标识。
- 桌面端左侧为卡片列表，右侧为选中记录的六维雷达缩略图和六维数值。
- 移动端改为上下布局。
- “查看完整报告”复用同一个报告内容组件，以历史快照为数据源。
- 历史完整报告继续支持截图和 PDF。
- 历史列表不显示未完成草稿。

### 10.4 空状态与异常状态

- 无真实记录：显示“尚未生成能力报告”和“开始测评”。
- 当前报告进行中：显示类型、实时进度和已测维度。
- 存储失败：页面保留当前内存结果，同时显示持久化警告。
- 历史为空：显示解释性空状态，不显示演示记录。
- 记录缺损：该卡片显示“数据不可用”，不让整个报告页面崩溃。

## 11. 组件和责任边界

### 11.1 评分 Skill

评分 Skill 是算法唯一来源，包含浏览器安全的纯函数核心。它负责：

- 输入校验；
- 单题得分率；
- 多选防猜；
- Rasch 六维估计；
- 总百分比与评级；
- 标准化结果结构；
- 题库校验；
- 命令行评分。

它不负责 React 状态、页面跳转、动画、localStorage 或报告排版。

### 11.2 Attempt 管理层

项目中的 Attempt 管理层负责：

- 创建、恢复、重开和完成 Attempt；
- 把提交答案转换为评分核心输入；
- 保存草稿与历史；
- 维护最新报告引用；
- 生成客观题固定试卷；
- 保持综合测评自适应状态。

### 11.3 React 界面层

React 组件只负责：

- 展示题目和反馈；
- 提交用户答案；
- 展示实时结果、历史列表和报告；
- 调用 Attempt 管理层；
- 显示恢复、重开与存储错误状态。

评分公式不得复制到 React 组件中。

## 13. 测试策略

### 13.1 评分核心单元测试

- 单选和判断的正确、错误结果；
- 多选完全正确、仅漏选、漏选加错选、全选、只选错误、空选择；
- 得分率限制在 `0～1`；
- 高难度正确比低难度正确提供更强正向证据；
- 高难度错误比低难度错误提供更弱负向证据；
- 相同作答换序后结果完全相同；
- 一道题只影响其 `dimKeys`；
- 无证据维度为 `null`；
- 所有非空维度分数为 `0～100` 的整数；
- 总百分比和评级边界；
- 无效题型、难度、答案或维度产生明确错误。

### 13.2 客观题试卷测试

- 恰好 5 关 × 5 题；
- 无重复；
- 难度总量为低 7、中 10、高 8；
- 各关难度配额准确；
- 六个维度都有覆盖；
- 尽量避免连续题型；
- 相同种子结果相同；
- 不同种子能够产生不同有效试卷；
- 作答不会改变剩余试卷。

### 13.3 Attempt 与持久化测试

- 新 Attempt、提交答案、完成和重开；
- 第一题提交后更新 `latestReportRef`；
- 综合和客观互相覆盖当前报告但不删除历史；
- 每题提交后草稿可序列化恢复；
- 完成后草稿转历史；
- 进行中无正式评级；
- 损坏 JSON 备份与安全恢复；
- localStorage 写入失败时保留内存结果并返回警告；
- 不兼容草稿不继续执行；
- 历史快照不随新评分版本重算。

### 13.4 界面与回归测试

- 综合测评仍按第一版算法选题；
- 客观题每关五题并显示即时反馈；
- 报告从固定数据切换为真实 Attempt 数据；
- 实时雷达、待测维度、进行中进度、完成评级；
- 空状态；
- 历史筛选、卡片、侧边预览和完整报告弹窗；
- 截图和 PDF 使用当前查看记录的数据；
- 原有报告对话、建议和资源保留；
- 个人中心报告弹窗继续工作；
- 所有现有测试保持通过。

### 13.5 Skill 验证

- Skill 自带测试通过；
- 命令行示例可执行；
- 题库校验通过；
- 同一输入经 Skill CLI 与应用调用得到相同结果；
- ZIP 解压后结构完整且不依赖项目路径。

### 13.6 浏览器端到端验证

使用真实浏览器完成以下流程：

1. 综合测评提交答案，验证最新报告立即切换并实时更新；
2. 刷新后恢复综合测评；
3. 完成五关，验证评级与历史记录；
4. 启动客观题，验证 25 题固定试卷和即时反馈；
5. 客观题第一题提交后覆盖当前报告；
6. 刷新后题目计划和进度不变；
7. 完成后验证新的历史卡片；
8. 筛选、侧边预览、完整报告、截图和 PDF；
9. 验证没有真实记录时的空状态；
10. 验证综合测评自适应轨迹没有因评分接入发生变化。
