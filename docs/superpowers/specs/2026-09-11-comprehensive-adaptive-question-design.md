# 综合测评自适应出题设计

## 目标

把综合测评现有的“进入关卡时随机抽取五题”改为逐题自适应选择。系统在用户提交当前答案后，结合本次综合测评中已经观察到的作答结果、能力维度覆盖和题型分布，决定下一题。自适应状态跨五关延续，并在进入新关时向中等难度部分回归。

本改动只负责出题。它不新增总分、百分制成绩、等级、能力雷达图、测评报告或持久化成绩，也不把内部路由状态传给现有觉醒报告。

## 当前实现

- 综合测评有五个主题关卡，每关固定完成五题。
- `src/comprehensive-quiz.js` 在关卡挂载时从该关的二十四题中随机抽取五题。
- `src/comprehensive-questions.json` 有一百二十题。每题包含关卡、题型、答案、解析和两个能力维度，但没有难度字段。
- Word 原始题库把第一至第四十题标为低难度，第四十一至第八十题标为中难度，第八十一至第一百二十题标为高难度。三个难度各四十题，题目顺序与 JSON 的 `q001` 至 `q120` 一致。
- 每个主题关卡在每个难度下各有八题，因此逐题选择时有稳定的相邻难度候选池。

## 范围

### 包含

- 为每道综合测评题补充明确的 `difficulty` 元数据，取值为 `low`、`medium` 或 `high`。
- 新增可独立测试的自适应会话和候选题选择函数。
- 综合测评改为一次只选择当前题，在提交答案后选择下一题。
- 自适应状态跨五关保留，进入新关时向中等难度部分回归。
- 避免同一次综合测评中重复出题。
- 在难度适配的基础上补足能力维度，并减少题型连续重复。
- 在同样适合的候选题之间加入可注入随机源的随机选择，降低固定题目曝光。
- 保留每关五题、现有即时反馈、答案解析、故事对话和关卡完成流程。

### 不包含

- 新增或修改最终评分规则。
- 生成或展示内部能力值、分数、等级或报告。
- 修改客观题测评、对话式测评或实操任务测评的出题方式。
- 把状态写入 localStorage、服务端、账号资料或报告记录。
- 引入 IRT、题目反应理论参数、机器学习模型或后端服务。
- 修改题目文本、选项、答案或解析。

## 数据模型

每道综合题增加字段：

```json
{
  "id": "q001",
  "difficulty": "low"
}
```

难度映射固定为：

- `q001` 至 `q040`：`low`
- `q041` 至 `q080`：`medium`
- `q081` 至 `q120`：`high`

测试必须验证总数为低、中、高各四十题，并验证每个关卡在每个难度下各八题。这样以后调整题库时，错误的难度分布会立即被发现。

## 自适应会话状态

综合测评使用页面内存中的临时会话：

```js
{
  position: 1,
  usedQuestionIds: [],
  dimensionCounts: { D1: 0, D2: 0, D3: 0, D4: 0, D5: 0, D6: 0 },
  typeCounts: { single: 0, judge: 0, multi: 0 },
  lastType: null,
  activeStage: null
}
```

`position` 只是一项不可见的出题路由信号：`0` 接近低难度，`1` 接近中难度，`2` 接近高难度。它不是成绩，不对用户展示，也不离开综合测评组件树。

## 路由信号更新

会话从 `position = 1` 开始。每道题提交后：

- 完全正确：`position + 0.4`
- 多选题部分正确：`position` 不变
- 错误：`position - 0.4`
- 结果始终限制在 `0` 至 `2`

该步长意味着一次偶然结果不会立即把后续题目推到难度极端；连续两次同方向结果才会形成明显难度偏移。

进入新的关卡时，且该关不同于上一次已经开始的关卡，执行：

```js
position = 1 + (position - 1) * 0.65
```

该计算保留前面关卡的证据，同时把极端位置拉回中等难度。重复打开同一关不会重复执行回归。

## 下一题选择

选择器接收当前关卡题池、会话状态和可注入的随机函数，依次完成以下工作：

1. 排除 `usedQuestionIds` 中的题目。
2. 为每个候选题计算选择优先级。
3. 按优先级排序并取前三个候选题。
4. 使用注入的随机函数在前三个候选中选择一题。
5. 如果候选不足三个，则在所有现有候选中选择。

候选题使用稳定的字典序规则排序，避免不同权重相加后产生难以解释的结果：

1. 难度索引与 `position` 的绝对距离越小越优先。
2. 两个 `dimKeys` 在 `dimensionCounts` 中的计数之和越小越优先。
3. 与 `lastType` 不同的题型优先。
4. 以上三个条件相同的候选保留原题库顺序。

排序后只在前三个候选中随机选择。这样难度匹配始终是硬优先级，维度和题型只在难度同等合适时调整选择。

### 难度匹配

将 `low`、`medium`、`high` 映射为 `0`、`1`、`2`。候选题难度越接近当前 `position`，优先级越高。难度匹配是最主要的因素。

### 能力维度补偿

每道题的两个 `dimKeys` 都计入 `dimensionCounts`。候选题包含当前出现次数较少的维度时获得额外优先级，避免五题全部集中于相似能力。

维度补偿只在难度大致合适的候选中发挥作用，不能让明显不匹配的难度仅凭维度标签成为首选。

### 题型多样性

候选题型与 `lastType` 不同时获得小幅优先级。题型多样性低于难度匹配和维度补偿，避免为追求一道稀缺多选题而选择明显不合适的难度。

由于部分关卡和难度组合没有多选题，选择器不规定每关必须包含某种题型，只减少可避免的连续重复。

## 候选耗尽和回退

正常情况下，每个关卡有二十四题而只需五题，不会耗尽。选择器只从当前关卡中尚未使用的题目选择；如果没有未使用题目，则返回明确的 `null`，由界面显示无法继续的错误状态，而不是重复出题、崩溃或静默完成关卡。

## React 集成

自适应会话由 `SiteExperience` 持有，使综合测评任务组件在返回地图和进入下一关时仍能访问同一会话。状态只传给综合测评；其他三类测评继续使用原来的组件属性和流程。

`ComprehensiveTask` 的行为改为：

1. 进入关卡并完成开场对话。
2. 请求选择器生成当前题。
3. 用户作答后继续调用现有 `judgeComprehensiveAnswer` 产生即时反馈。
4. 把 `correct`、`partialCorrect` 或错误结果转换为路由结果，更新会话。
5. 用户点击继续时，基于更新后的会话选择下一题。
6. 完成第五题后进入现有结尾对话并完成本关。

当前题目需要保存在组件状态中，而不是从预生成的五题数组按索引读取。题号仍显示为第一至第五题。

## 会话生命周期

- 初次进入综合测评地图时创建会话。
- 从关卡返回地图时保留会话。
- 从地图进入下一关时保留并执行一次关卡回归。
- 离开综合测评返回 TEST 选择页时清空会话，下一次进入从中等难度重新开始。
- 浏览器刷新不会恢复会话。
- 进入其他测评不会读取或更新综合测评会话。

## 错误处理

- 题库缺少或包含非法难度时，数据测试失败。
- 选择器收到空关卡题池时返回 `null`。
- 界面遇到 `null` 时显示可读错误并允许返回关卡地图，不自动把关卡标记为完成。
- 注入的随机函数结果在选择前限制到合法数组索引，避免自定义测试随机源产生越界。

## 测试策略

### 纯函数测试

- 会话从中等位置和空覆盖记录开始。
- 完全正确、部分正确和错误按规则更新位置并限制边界。
- 跨关卡回归只在关卡实际变化时执行一次。
- 已使用题目不会再次被选择。
- 难度相同时优先补足较少覆盖的能力维度。
- 其他条件相近时减少连续相同题型。
- 固定随机源能得到确定结果。
- 空题池返回 `null`。

### 数据测试

- 一百二十道题都有合法难度。
- 三个难度各四十题。
- 每个关卡在每个难度下各八题。
- 题目 ID 唯一，题型和维度字段仍然有效。

### 集成与回归测试

- `ComprehensiveTask` 不再调用一次性随机抽取五题的旧接口。
- 当前题提交后才会请求下一题。
- 综合测评状态由 `SiteExperience` 持有并在离开综合测评时重置。
- 客观题、对话式和实操任务测评不接入自适应状态。
- 运行全部 Node 测试、Vite 构建和 Sites Worker 测试。

## 验收标准

- 综合测评每关仍然正好完成五题。
- 第一关第一题从中等难度附近开始。
- 连续正确会使后续题目整体趋难，连续错误会使后续题目整体趋易，交替作答不会频繁跳档。
- 自适应状态跨五关延续，并在新关开始时部分回归中等难度。
- 已答题目不重复，能力维度覆盖优先得到补足，题型不会在有合适候选时无谓连续重复。
- 用户界面不显示任何新增分数、能力值、等级或报告。
- 其他三种测评行为不变。
