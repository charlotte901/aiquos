# 《AIQUOS 优化建议 100 条》

AIQUOS 目前以纯前端形态（React 19 + Vite + localStorage）完整跑通了「免验证登录 → CHOOSE 选择 → 综合测评 5 关 × 5 题 → 智核觉醒报告 → 个人中心·测评记录」的全链路，并已具备冻结版六维评分引擎（vendor/aiquos-six-dimension-scoring 1.0.0）、自适应选题（src/comprehensive-adaptive.js）与 124 条 node --test 测试的良好工程基础。本文档面向企业级演进方向，从工程化、用户体验、视觉审美与测评专业性四个维度给出 100 条具体建议，其中 30 条标注 ✅ 为建议优先落地的高收益低风险项。所有建议均不触碰既定约束：评分核心 vendor 保持冻结、每关 5 题与剧情对话/即时反馈/地图流程保留、演示定位不变。

## 一、企业级与工程化（1-30）

**✅ 1. 渐进引入 TypeScript 类型体系**：当前无任何类型约束，而测评状态（attempt 草稿、history 快照、自适应隐藏态）字段多且嵌套深。建议先用 JSDoc + tsconfig（checkJs）覆盖评分适配层、comprehensive-adaptive.js 与持久化模块，再逐步迁移 .tsx，在不改构建的前提下拦截大量字段拼写与结构回归。

**2. 建立 ESLint + Prettier 基线**：仓库尚无 lint/格式化配置，多人协作后风格会快速漂移。接入 eslint-plugin-react-hooks 与 Prettier 并纳入 pre-commit 钩子，统一风格的同时杜绝 hooks 依赖数组误用。

**✅ 3. 搭建最小 CI 流水线**：目前 124 条 node --test 与 vite build 只能靠本地自觉执行。新增 GitHub Actions，在每次 push/PR 自动跑 lint + test + build，几分钟内给出红绿结论——这是其余所有工程化建议的前置项。

**✅ 4. localStorage 安全写入封装**：Safari 隐私模式或配额已满时 setItem 会抛 QuotaExceededError，直接导致 aiquos.comprehensive-attempt.v1 草稿写入失败甚至中断测评。封装 safeSetItem（try/catch + 失败 toast + 内存副本降级），保证任何环境下测评不因存储异常而崩溃。

**✅ 5. 数据版本迁移框架**：aiquos.comprehensive-history.v1 内嵌不可变快照结构，未来字段演进（如增加题库版本、作答用时）会破坏旧记录。在读取入口加 migrator 链（v1→v2 逐级升级）并保留原始字节备份，让 12 条历史快照平滑升级而非被丢弃。

**6. 读取侧 Schema 校验**：用户手动改过 localStorage 或写入被截断时，损坏的 history 会让个人中心渲染崩溃。读取时做轻量结构校验（zod 或手写 assert），异常数据隔离到 .corrupt 后缀 key 并提示「部分记录已损坏」，而非整页白屏。

**7. 草稿写入的节流与刷盘时机**：当前每题作答都同步写 attempt.v1，连续操作下写放大明显。改为 300ms 节流 + 在 visibilitychange/pagehide 时强制 flush，兼顾数据安全与主线程性能。

**8. 页面生命周期保护**：综合测评进行中刷新或关闭页面没有任何提示。监听 beforeunload 弹出确认，文案同时告知「进度已自动保存，可随时回来继续」，把技术兜底转化为用户安心感。

**✅ 9. 按路由面板引入 ErrorBoundary**：panels stay mounted while hidden 的架构下，任一面板（如 AwakeningReport.jsx）渲染抛错会让整个应用白屏。为 #home/#choose/#assessment/#center 各面板包一层 React 错误边界，提供「重试 / 返回首页」而非全局崩溃。

**10. 全局异常采集环形缓冲**：用 window.onerror + unhandledrejection 收集最近 50 条错误到内存 ring buffer，并在设置面板提供一键复制导出，演示现场出问题时能快速定位，也是未来接入上报服务的预留接口。

**11. 报告结果快照固化**：completed 时把 vendor 引擎输出的六维分、overall、等级整体写入 history 快照，报告弹窗回放一律读快照而不重算。即使未来更换引擎版本，历史报告也保持不可变的一致性。

**12. 依赖锁定与审计**：three.js、React 19 等依赖锁定精确版本并接入 npm audit / dependabot，避免构建随上游小版本漂移，保证演示机器与 CI 产物一致。

**✅ 13. 构建体积预算**：vite build 后无人追踪包体，three.js 是主要大头。接入 rollup-plugin-visualizer 生成构成报告，并设定 size-limit 阈值（如首屏 gzip ≤ 350KB）作为 CI 卡口，防止体积无声膨胀。

**14. 按路由代码分割**：所有面板常驻挂载意味着全部代码都进入首屏 bundle。用 React.lazy 拆分 AssessmentFlow.jsx、AwakeningReport.jsx 与 ProfileHub.jsx，首屏只保留 #home 立方体所需模块，明显缩短可交互时间。

**15. WebGL 上下文丢失恢复**：three.js 立方体在长时间演示或系统休眠后可能触发 context lost。监听 webglcontextlost/restored 事件，丢失时展示静态降级画面并自动重建场景，避免出现黑块。

**16. 隐藏面板暂停渲染循环**：面板隐藏但保持挂载时，若 cube-scene.js 的 RAF 循环仍全速运行会浪费电量。通过路由可见性判断，在 #assessment 等非首页路由暂停立方体动画帧循环，回到 #home 再恢复。

**17. Web Vitals 本地采集**：接入 web-vitals 对 LCP/INP/CLS 做内存采集，在开发者面板展示最近指标，让「演示也很流畅」变成可量化的话术，并为性能回归提供基线。

**✅ 18. 测试覆盖率门槛**：124 条 node --test 是好基础，但缺少覆盖率视图。用 c8 生成报告，对 vendor 适配层、comprehensive-adaptive.js、持久化模块设 ≥90% 行覆盖的 CI 门槛，守住最核心的回归面。

**19. 自适应模块属性测试**：对 position walk（±0.4 步进、×0.65 回归、3 候选曝光）在 tests/comprehensive-adaptive.test.mjs 基础上补充 property-based 测试：随机作答序列下断言难度位置始终有界、单次 run 无重复题、维度覆盖单调不减，把隐式不变量显式固化。

**20. Playwright E2E 冒烟链路**：补一条端到端用例：免验证登录 → 综合测评 5 关 × 5 题完成 → 觉醒报告生成 → 历史记录出现并可打开弹窗，防路由与流程级回归，是每次对外演示前的最后保险。

**21. 报告视觉回归基线**：AwakeningReport 的六维雷达、等级徽章、分段建议用 Playwright 截图建立基线，样式意外漂移时 CI 直接标红，保护最重要的「门面」页面。

**22. 环境配置分层**：用 import.meta.env 区分 demo/build 的文案与开关（如是否显示调试面板），提供 .env.example 入库，避免硬编码的演示假设散落在各组件里。

**✅ 23. 路由常量与构造函数集中管理**：#assessment/<id>/level/<n>、#center/<id>、#forum/<view> 等字符串散落各处，极易拼错。收敛为单一 routes 模块并提供建构/解析函数，路由规则变更只需改一处。

**24. 深链接参数校验**：直接输入非法的 assessment id 或越界 level（如 level/9）时应展示友好兜底页并引导回 #choose，而非渲染空白面板或直接抛错。

**25. 无障碍基础审计**：prefers-reduced-motion 已被尊重是亮点，但按钮 aria-label、图片 alt、色彩对比度尚未系统化。用 axe-core 跑一轮全路由审计形成问题清单，逐项修复。

**26. 键盘全链路导航**：对话推进、选项选择、提交、弹窗关闭都应可纯键盘完成，焦点管理遵循「可见即可达」原则，同时为键盘用户与未来的 E2E 自动化铺路。

**27. 文案 i18n 抽离**：剧情对话、关卡名、报告文案目前硬编码在组件中。抽取为 locale 资源文件（JSON），即便暂不做多语言，也便于文案校对、术语统一与后续国际化。

**✅ 28. 隐私说明与一键清除数据**：测评数据全存于本机 localStorage。在个人中心/AccountSettings 提供「数据存储说明 + 清除全部数据」入口，展示涉及的 key 清单（attempt/history/case-journey），以合规姿态对齐企业级预期。

**29. 数据导出与导入**：history 上限 12 条且无法迁移设备。提供 JSON 一键导出全部记录与草稿、以及导入合并（按快照 id 去重），支撑换机与演示备份场景。

**30. 架构决策记录（ADR）**：把「vendor 评分引擎冻结不可改、每关 5 题、objective-bank-v6-120、latest 12 快照」等关键约束写成简版 ADR 附于 README，任何接手者第一眼就知道哪些是不能碰的红线。

## 二、用户体验（31-60）

**✅ 31. 未完成草稿的显式恢复引导**：attempt.v1 支持续答，但用户未必察觉。检测到未完成草稿时在测评入口展示恢复卡片（显示「第 X 关 · 第 Y 题 / 共 25 题」与开始时间），提供「继续上次测评 / 重新开始」双按钮，把技术能力变成可感知的体验。

**32. 本机存储的期望管理**：草稿与历史仅存当前浏览器，换设备即消失。在免验证登录成功页与 CHOOSE 页加角标提示「数据仅保存在本机」，避免演示后用户误以为存在云端账号。

**33. 草稿恢复的状态还原粒度**：恢复续答时，已作答题目的所选答案、对错状态、是否已看解析都应从 draft 完整还原，退出重进不产生状态丢失或重复计分。

**34. 恢复后即时反馈的重放**：回看已答题目时重新呈现当时的对错、正确答案、解析与守护者反应（可折叠），而不是只剩题干，保证「回看」与「新答」体验一致。

**35. 测评中途退出的确认与安抚**：TEST 流程中点返回或切换路由时提示「进度已自动保存，可从个人中心·测评记录继续」，并说明重新开始将覆盖草稿，防止误触清空 20 分钟的努力。

**✅ 36. LiveDimensionStrip 的进行中说明**：进行中只展示有证据的维度分、无总分无等级，是严谨的设计，但易被误读为「漏评」。在 AssessmentFlow.jsx 的维度条带旁加提示：「已作答题目尚未覆盖全部六维，完成后生成总分与等级」，管理用户预期。

**37. 关卡结尾的叙事化过渡**：五关（智核学院/信息迷城/创客工坊/协同空间站/伦理殿堂）切换的结尾对话中，由守护者预告下一关主题与使命，把进行中「无总分无等级」的设计转化为「觉醒前夕」的叙事悬念，而非生硬留白。

**✅ 38. 报告计算透明度**：AwakeningReport 增加「分数如何得出」折叠说明：难度锚点 -1/0/+1、N(0,1) 后验、多选题部分得分 clamp(hitRate − 0.6×wrongRate, 0, 1)、overall = 六维均值四舍五入。透明换信任，面向企业客户演示时尤其如此。

**39. 导出文件命名与失败降级**：截图/PDF 保存采用带信息的文件名（如 AIQUOS_报告_20260919_等级S.png），并对浏览器拦截下载或 PDF 生成失败给出明确提示与重试入口。

**40. 分享卡片生成**：基于报告数据生成 9:16 分享图（六维雷达轮廓 + 等级徽章 + 一句话评语 + 品牌角标），把演示成果转化为传播素材。

**✅ 41. 历史 12 条上限的用户告知**：aiquos.comprehensive-history.v1 仅保留最新 12 条不可变快照，达上限会静默淘汰最旧记录。接近上限时提示并提供「导出即将淘汰的记录」，不让数据无声消失。

**42. 日历与记录的深度联动**：个人中心日历在完成日标记等级色点、进行中标记空心点，hover/点击展示当日测评摘要并直达报告弹窗，让日历从装饰变成导航。

**✅ 43. 报告弹窗的可访问性与滚动锁定**：打开历史报告弹窗时焦点移入弹窗、支持 Esc 关闭、关闭后焦点返回触发元素，并锁定背景滚动，符合对话框交互最佳实践。

**44. 关卡进度全局可视**：地图流程保留的前提下，在测评页顶部增加 5 段式进度条（关卡名 + 当前高亮 + 关内 5 题小圆点），降低 25 题长流程中的迷失感。

**45. 剧情对话的跳过与回看**：开场/结尾剧情必须保留，但应为二刷用户提供「跳过本段」按钮与对话记录回看入口，兼顾叙事完整与效率。

**✅ 46. 打字机效果的可控性**：剧情逐字显示支持点击立即补全当前句，并提供全局「快速对话模式」开关；prefers-reduced-motion 用户直接呈现全文，把已有的尊重策略升级为主动可控。

**47. 多选题的交互防误**：客观题多选类型提供已选计数提示与提交前确认态（如「已选 2 项」），防止误提交；提交后锁定并高亮正确项与漏选项。

**48. 解析缺失的兜底文案**：个别题目解析较短或缺失时，即时反馈区会出现结构空洞。统一兜底文案（守护者口吻的「本题解析整理中」）与占位样式，保证反馈区永远完整。

**49. 作答时长的本地记录**：每题作答时长随答案一并写入 draft（不参与评分），完成后在报告附录展示平均用时与最慢题目，增强专业观感并为后续题目难度校准积累数据。

**50. 守护者反应的多样化**：即时反馈中守护者反应目前与对错强绑定，台词重复率高。按维度、连对/连错、关卡进度扩充反应池并加权去重，让 25 次反馈不千篇一律。

**✅ 51. CHOOSE 页新手导览**：综合测评/客观题/对话式/实操四种类型的差异，首次进入时用 30 秒分步导览或对比卡片讲清「测什么、多久、出什么报告」，降低选择焦虑。

**52. 免验证登录的说明前置**：登录页明示「演示环境无需真实手机号/邮箱，任意昵称即可进入，数据仅存本机」，避免用户寻找验证码而流失。

**✅ 53. 全站空状态治理**：#reports 无报告、#center 无历史、#forum/<view> 无内容时多为空白面板。统一空状态组件：插画 + 一句话说明 + 主行动按钮（去测评/回首页），任何入口不留死角。

**54. 加载与过渡态**：报告生成、历史读取等异步间隙使用骨架屏而非空白，转场统一 150-250ms，让感知性能与实际性能同步提升。

**✅ 55. 移动端适配审计**：3D 立方体与 DOM 投影屏在窄屏下可用性下降。为 <768px 提供降级策略（立方体降为静态案例轮播卡片、字号与触控间距单独一档），保证手机演示不翻车。

**56. 触控目标尺寸规范**：选项卡片、按钮、关闭符等可点区域 ≥44×44px 并保持 8px 以上间距，减少误触，同时惠及移动端与触屏设备。

**57. 异步动作的统一重试模式**：PDF 导出、截图保存、数据导入等异步操作统一 loading/retry/error 三态与 toast 文案规范，避免各处自造轮子导致体验不一致。

**58. 快捷键体系与帮助**：定义全局快捷键（数字键选选项、Enter 提交/推进对话、Esc 关闭弹窗、? 呼出帮助面板），并在帮助中一览展示，测评熟手可显著提速。

**✅ 59. 提交前的反悔窗口**：单选/判断题误触后、提交前允许改选（高亮「未提交」状态），提交后不可修改但可回看解析，交互规则在题目卡片上一句话讲明。

**60. 完成页的下一步引导**：觉醒报告末尾提供「查看历史对比 / 分享成绩 / 再测一次」三联行动区，把单次测评接入复测与传播的闭环。

## 三、视觉与审美（61-85）

**✅ 61. 设计令牌（design tokens）收敛**：颜色、字号、间距、圆角、阴影目前分散在各面板样式（styles.css、assessment-flow.css、forum.css 等）中。抽为 CSS 自定义属性单源管理并文档化语义（如 --color-grade-s），是后续主题能力与一致性的地基。

**62. 暗色/亮色双主题**：现有深空科技风适合暗色，但企业演示常在明亮会议室。以 data-theme 属性 + prefers-color-scheme 提供双主题，令牌化完成后成本低、收益大。

**✅ 63. 等级色彩语义系统**：S/A/B/C/D 五级色在雷达、徽章、历史列表、日历色点中全端统一（S 金/A 紫/B 蓝/C 青/D 灰一类方案），形成「看到颜色即知等级」的条件反射，强化品牌记忆。

**64. 雷达图参考环与峰值标注**：AwakeningReport 六维雷达增加外圈刻度参考环与最强/最弱维度自动标注连线，引导视线直接落在报告结论上。

**✅ 65. 中文长文本阅读规范**：题目与解析正文统一 ≥15px、行高 1.7、段落宽度约束（每行约 36-38 字），即时反馈里的长解析可读性立竿见影。

**66. 中英混排细节**：AIQUOS、D1-D6、TEST 等西文与中文之间的间距、字重、大小写统一处理，消除「翻译腔」排版的廉价感。

**67. 空状态插画体系**：空报告、空历史、加载失败共用一套与「智核世界观」一致的线性插画 + 守护者口吻文案，把空状态做成品牌触点而非留白尴尬。

**68. 品牌识别系统**：Logo、favicon、加载态、报告水印统一以「立方体/智核」为核心符号延展，形成可被记住的视觉资产而非散点装饰。

**69. 动效语言三级分层**：页面级转场、组件级悬浮/展开、反馈级对错动效统一时长与缓动曲线（如 200ms / cubic-bezier(0.2, 0, 0, 1)），全站节奏一致才显高级。

**✅ 70. 对错反馈的双通道设计**：答对/答错除颜色外增加动效区分（对 = 扩散光环、错 = 轻微震动 150ms），并确保 prefers-reduced-motion 下退化为纯色块 + 图标，信息不丢失。

**71. 加载韵律统一**：骨架屏 shimmer、按钮 loading、立方体待机旋转共用同一节奏参数，消除各处 spinner 各自为政的视觉杂音。

**72. 图标系统单套化**：自绘或引入单一线性图标集（SVG sprite），替换混用的多风格图标与 emoji，线性粗细与圆角和整体 UI 对齐。

**73. 3D 场景的性能感知降级**：依据 deviceMemory/hardwareConcurrency 判断低端设备，自动降低立方体帧率或切换静态渲染，保住首屏流畅的优先级。

**74. 投影屏内容的可读性保障**：DOM-projected screens 处于透视变形下时，关键文案保证最小字号与对比度，或在面板底部冗余一份正交视图，美观不牺牲可读。

**✅ 75. 层级体系（elevation）统一**：卡片、弹窗、下拉三层阴影 + 描边规范固化进令牌，消除「每个面板一个风格」的拼贴感，这是最便宜的一致性收益。

**76. 报告页 F 型信息动线**：觉醒报告重排为「雷达总览 → 等级徽章 → 六维分述与分段建议 → 资源推荐 → 导出」的浏览动线，首屏一屏内给到最重要结论。

**77. 长解析折叠机制**：即时反馈中超过三行的解析默认折叠为「展开解析」，保持答题节奏，展开后记住滚动位置，兼顾深度与流畅。

**78. 日历的数据墨水比**：个人中心日历削减装饰性底纹，强化数据编码（完成日等级色点、连续测评周高亮），让装饰让位于信息。

**80. 对话气泡规格统一**：剧情对话的姓名牌、头像框、光标、情绪标点动画定义统一组件规格，守护者形象在不同关卡间保持一致识别。

**81. 滚动行为规范**：长页面统一 scroll-margin-top 与锚点跳转平滑滚动，并在 prefers-reduced-motion 下自动关闭 smooth，细节处见工程素养。

**82. 焦点可见样式品牌化**：为 :focus-visible 设计与整体科技风一致的发光描边，键盘导航时既醒目又不突兀，无障碍与审美兼得。

## 四、测评专业性与算法（86-100）

**✅ 86. 题库版本写入报告与快照**：objective-bank-v6-120 的版本号目前只存在于代码中。将 bankVersion 写入 history 快照并在报告页脚标注「基于 v6 题库（120 题）」，未来扩库后新旧结果可被正确解释。

**✅ 87. 跨场次曝光均衡统计**：no-repeat 只在单次 run 内生效，120 题库对多次测评用户的重复率会逐渐升高。在本地聚合每题历史曝光计数，自适应 3 候选打分时给低曝光题加权，提升题库利用率与复测新鲜感。

**88. 题目经验难度校准**：low/medium/high = -1/0/+1 的三档锚点粒度较粗。持续累积本地作答正确率后，在不改 vendor 的前提下微调题库标注（如稳定 85% 正确率的 high 题降为 medium），让锚点更贴近真实。

**✅ 89. 自适应状态可视化调试面板**：position walk（±0.4）与 ×0.65 回归目前是隐藏状态，调参与讲解都靠脑补。开发者面板绘制本次 run 的难度轨迹与各维度覆盖热力图，演示时也能直观讲述「自适应在做什么」。

**90. 部分给分的透明计算展示**：多选题 clamp(hitRate − 0.6×wrongRate, 0, 1) 对用户是黑盒。在解析区展示「选对 2/3、错选 1 → 本题得分 0.4」式的明细，严格感即是专业感。

**✅ 91. completed 前置条件的用户提示**：answeredCount === 25 且六维均有证据才判定 completed，若某维度始终无证据将静默无法完成。在关卡进度处实时校验并提示「尚需 1 题以覆盖 D6 伦理维度」，把失败模式提前暴露而非留到最后。

**92. 分数置信区间示意**：基于引擎 N(0,1) 后验为六维分附示意性区间（如 D2：72 ± 6），报告注明「区间为算法不确定性估计」，管理分数边界的期望（89 与 91 的差异未必显著）。

**93. 题目-维度覆盖矩阵审计**：将 120 题 × D1-D6 的标注矩阵可视化（每维证据题数、每关维度分布），入库前检查每维至少 3 题可被 25 题路径覆盖，防止结构性盲区。

**94. 练习效应控制**：同用户二刷时优先过滤其历史已答题目（结合第 87 条的曝光计数），保证「再测一次」测的是能力变化而非题目记忆。

**95. 作答模式软标记**：全同选项、极短作答时间（结合第 49 条的时长记录）在本地打异常标记，报告页仅以「本次作答模式较特殊，结果仅供参考」的温和提示呈现，不惩罚、不阻断。

**96. 关卡内难度节奏约束**：在自适应候选打分中叠加关卡内位置先验（前 2 题偏中低难度热身、后 3 题收紧区分度），与剧情节奏（开场建立信心 → 结尾制造张力）对齐，测量与叙事双赢。

**97. 题库治理入库清单**：为 v7 扩库制定 checklist：维度标注、难度锚点、解析完整性、守护者反应映射、术语一致性审查，并附样例题模板，防止规模扩张带来质量漂移。

**✅ 98. 多次测评对比报告**：利用 history 12 条快照，在个人中心提供六维重叠雷达/趋势折线的对比视图（选取 2-4 次），直观呈现成长曲线，是提升复测动机的最强钩子。

**99. 等级边界与整体分说明**：报告明示 S≥90/A≥80/B≥70/C≥60/D<60 与「overall = 六维均值四舍五入」，并对 79.5→80 这类边界跳级情形加注说明，消除用户对「差 0.5 分」的争议。

**100. 评分引擎演进隔离层**：vendor 1.0.0 冻结的前提下，业务侧通过统一 wrapper 调用评分；未来若出现 2.0 可并行双跑对比输出（影子计算）后再切换，存量历史报告永远读旧快照，升级零风险。
