### P1
1. **verifyToken 对畸形签名段抛异常**（worker/account-store.js）：`fromB64url(parts[2])`
   在 try 之外，`v1.<合法body>.!!!` 会抛 Invalid character 而非返回 null——
   fail-closed 不构成绕过，但能把请求打成 500/挂死。已并入 try。
2. **登录限速键可伪造**（worker/auth.js）：`x-forwarded-for` 首段是客户端自报值，
   换假 IP 即无限速爆破；且键未 normalize（`" 138…"` 与 `"138…"` 分桶）。
   已改为 cf-connecting-ip 优先、XFF 只取最后一段、键用 normalizeAccount。
3. **cleanScore(null)===0**（worker/data-store.js）：`Number(null)===0` 把「通道缺分」
   静默存成 0 分（对话/实操缺分是常态），answeredCount/totalQuestions 同病。
   已先挡 null/undefined/空串再谈数值（cleanCount 同）。
4. **题库写接口零鉴权**（worker/admin.js）：PUT/DELETE 任何人可调，与严格登录
   目标冲突。已要求教师 Bearer（GET 保持公开——题库内容本就下发学生端）；
   admin/api.js 的 saveBank/reset 改带令牌。

## 审计确认无问题的方面

- **认证密码学**：PBKDF2-SHA256 100k 迭代 + 独立盐、恒定时间比较（哈希与
  HMAC 双处）、exp 强制、角色取自 store 记录而非 token payload（无提权路径）、
  账号不存在等耗时 dummy 派生（时序探测无注册面）、教师邀请码服务端强制。
- **XSS**：新代码零 innerHTML/dangerouslySetInnerHTML；入站字符串净化（控制字符
  剥离 + 限长）+ React 转义；`<script>` 字符串落库有测试。
- **契约一致性**：快照→上报负载字段与 snapshotAttempt/buildComposite 输出对齐；
  13 条路由（worker/index.js 与 vite 中间件）共用同一常量；storage key 三处一致。
- **数据净化与除零**：分数夹紧、维度白名单、averageScore/classAverage/weeklyTrend
  零分母守卫；null 保持无数据（P1-3 修复后）。
- **幂等/竞态**：run 重复上报原位替换；AssessmentHub/ProfileDetail/AdminApp 的
  effect 均 alive + 正确依赖（常驻面板 hidden 挂载时序已覆盖）；StrictMode 安全。
- **遗留回归**：favorites 随 accountId 迁移、cohort 离线回退、bank 版本契约
  （保存即晋升版本）未破坏；qa-full-e2e 登录段已改为注册一次性账号。
